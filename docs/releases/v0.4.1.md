# Auth 0.4.1 and Files 0.1.1

Module source tag `v0.4.1` publishes Auth 0.4.1 and Files 0.1.1 from one immutable Git snapshot. This is functional source distribution, not a new npm/crates.io Auth or Files package.

Both languages use published App SDK 0.1.2. Optional Console consumers use Console SDK 3.1.0. App 0.2.0 and the native CLI remain unchanged. Fresh installations work with Code 0.3.6; existing mixed SDK owners use Code 0.3.8 for the explicit patch migration below.

- Auth's existing Actions declare public operation/field schemas, capabilities and effects through SDK metadata. Discovery does not access credentials or providers.
- Files adds optional native SDK Actions over the existing stream methods; stream ownership and content bytes remain native. Metadata and content provider selection remain independent.
- Invalid input can carry safe field paths and fixed issue codes. Public HTTP errors preserve code/message and add optional issues; parser messages, input values, stacks and causes are excluded from the public projection.
- Source consumers and all generated catalogs require registry SDK 0.1.2. No local SDK patch or archive override is used.

Existing usernames, password hashes, sessions, metadata and blob layouts are unchanged. These metadata/error additions introduce no database migration. App 0.1.0 host upgrades remain explicit and retain sessions and disjoint user source changes. Code/provider updates do not move or delete stored application data.

When Auth 0.4.0 and Files 0.1.0 are already installed together, their shared SDK 0.1.1 requests must be coordinated. Code 0.3.7 adds an opt-in `patch_overrides` map. It preserves original owner requests and only projects a stable same-minor patch increase into the reviewed native manifest. It does not automatically relax conflicting requests.

Code 0.3.8 additionally keeps full Rust metadata-catalog validation within the existing Wasm execution budget. Upgrade Code to 0.3.8 first. Temporarily add `patch_overrides = { "@lenso/app" = "0.1.2" }` to the configured npm native target, or `{ "lenso-app" = "0.1.2" }` to the Cargo target, through `lenso ext configure code --input`. Preserve custom manifest, lock, program and offline settings. Review this configuration and the subsequent native plan, update Auth and Files, remove the override and preview/update once more. The official upgrade fixture exercises this public flow with existing sessions, >1 MiB content and user customizations on both databases.

For existing applications:

```sh
lenso ext add code --constraint '=0.3.8'
lenso ext configure code --input '{"ref":"HEAD"}'
lenso code preview auth --refresh
lenso code update auth
lenso code preview files --refresh
lenso code update files
lenso app check
```

If the existing Code selection has an exact version constraint, `ext update` retains it;
review the `ext add` operation above to replace that constraint explicitly. Reuse
your existing setup options when prompted. The `ref` configuration above selects
the current official module directory; generated modules still lock `v0.4.1`.
Keep any intentionally separate custom catalog configured separately.

Stop running application hosts before SDK/source updates and restart after checks. Review generated source and native dependency plans before applying them. Keep existing versions pinned if a customization needs migration. Files still requires the v2 application host and a trusted identity resolver.
