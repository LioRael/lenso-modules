# Auth 0.4.1 / Files 0.1.1 official release acceptance

Published module source is [v0.4.1](https://github.com/LioRael/lenso-modules/releases/tag/v0.4.1), signed source commit `c92a73bd9ef4d68dd7f371d9dcb33b56b9f9bf1d`. Auth 0.4.1 and Files 0.1.1 use registry App SDK 0.1.2. The canonical module directory selects immutable release catalogs; the official Registry also refreshes the hidden Auth compatibility preset. Use Code 0.3.8 for the migration in the [release notes](v0.4.1.md). Previously published tags and asset digests remain unchanged.

The primary workflow requires ten completed SDK consumers per job: two Auth directory consumers, two fresh App/Auth hosts, two fresh Files applications, two App 0.1.0-to-0.2.0 upgrades, and two Auth 0.4.0 / Files 0.1.0-to-current source upgrades. The legacy preset requires two consumers per job, with bidirectional storage adapter switching. Published Registry sources, extension assets and module tags are used throughout. Workflow dispatch does not build substitute App/Code Wasm or serve local module sources.

The [machine-readable record](v0.4.1-verification.json) preserves workflow checkout identities, artifact IDs and verified ZIP SHA-256 digests, platform/toolchain facts, installed registry SDK versions and per-project results. npm lock integrity and crates.io checksums are inspected before recording a consumer.

## Behavior covered

- Auth's optional Action/Module schemas and safe structured field errors are checked in actual TS/Rust consumers before and after source updates and provider switching. HTTP and native Actions reuse the same SDK descriptions.
- Files checks safe filename and size issues, authenticated chunked uploads of 1,049,287 bytes, byte-exact retrieval, two-user isolation, revoked sessions, restart persistence, physical deletion, and oversized/interrupted upload cleanup.
- Existing module-pair upgrades first prove that conflicting SDK owner requests are rejected without changing protected source, manifests, receipts or module indexes. The public configuration flow opts into the stable same-minor SDK patch, updates both modules, removes the override, and verifies that the final native receipt contains no override. Existing sessions, uploaded content and disjoint user source modifications survive.
- Old App host upgrades retain existing Auth sessions and user changes. Preview, consent denial, pending dependency preparation/retry and locked/offline replay are exercised through the real CLI.
- The historical Auth preset validates all three deterministic author samples, compiles and runs each provider, and retains original database data while switching providers. This includes the full Rust metadata-catalog fuel regression.
